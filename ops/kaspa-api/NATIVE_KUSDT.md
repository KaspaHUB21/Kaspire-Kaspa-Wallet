# Native kUSDT transport

The Android native KasPool builder produces node-ready wRPC JSON, not the SDK
wallet `serializeToSafeJSON` schema. The native swap alone uses
`https://kaspire.kaslab.space/api/native-kusdt`; other covenant clients and other
platforms retain their existing transport. Public Android 0.11.122 includes
this checked transport; the separate Android test builds preceded publication.

`scripts/native-kusdt-relay.mjs` forwards the original JSON text over the fixed
local node's JSON WebSocket port. It does not use the GothDAG application, load a
wallet SDK, sign, change witnesses or outputs, append scripts, or retry a send.
Only Mainnet, version-1 native transactions with the pinned KasPool/kUSDT
covenant IDs are admitted. The node still validates the entire transaction.
Integer validation is lossless, including u64s; compute budgets and covenant
bindings are retained. A submission reply is not a confirmation.

Recovery checks the accepted transaction and the node mempool first. Confirmed
or mempool transactions are not resubmitted. Unread/partial status remains
unknown. A definite node rejection is shown with its bounded error message.
No recovery operation signs a replacement transaction or erases the encrypted
pending journal on an error. A pool input spent by another trade may make the
old signed transaction unusable; no automatic new trade or discard is allowed.

The standalone service has no credentials or private-key access. It listens on
loopback, has bounded requests/concurrency/timeouts, omits transaction access
logs, and has no public-node fallback. `nginx-native-kusdt.conf` is an additional
location, not a replacement for the existing API. Install the checked script
under `/usr/local/lib/kaspire-native-kusdt/` with the supplied systemd service.

Tests cover the actual HTTP-to-WebSocket path against a local node fixture,
explicit rejection, dropped replies, wrong-chain/hash rejection, and recovery
states. Native buy/sell fixtures can be supplied with `KASPIRE_NATIVE_FIXTURES`;
they must be generated by the real builder/VM with disposable keys and fake
outpoints. Never use production signed transactions in these tests, and never
POST test fixtures to Mainnet. Live probes are GET/status/health only.
