# Android 0.11.29 (95) and extension 0.4.7 (47)

## Faster assets and alphabetical KRC20 lists

- Asset categories appear progressively instead of waiting for the slowest
  indexer, transaction history or market metadata. KAS remains independent.
- Both clients query KasLab KCC and Kasplex KRC20 token lists concurrently;
  a failed/invalid response does not mask a healthy mirror. Direct KNS and
  KRC721 discovery are independent of KRC20 and covenant categories.
- Android Kascov fallback inspects address-held tokens instead of querying
  up to 64 global token/holder documents per refresh.
- Extension category requests are deduplicated/cached briefly. Balance and
  UTXO provider calls no longer wait for token discovery.
- KRC20 tickers are sorted A–Z, including send selection. Token detail prices
  load independently when a user opens a token before enrichment finishes.

## KaspaCom seller PSKT fix, app and extension

- Sign-only underfunded seller drafts with selected `SINGLE|ANYONECANPAY`
  (132) inputs are supported. Each requires its same-index output.
- Missing buyer funding is not a network fee. Reviews show unknown final
  fee, missing input value and signature-bound payouts; signed SafeJSON is
  returned without a broadcast payload for unfunded offers.
- Other underfunded sighashes remain rejected. P2SH, duplicate outpoint,
  authorization/review binding and stale-session checks remain enforced.
- PSKT review addresses use the selected network prefix, including TN10.

Details: [seller-offer documentation](https://github.com/KaspaHUB21/Kaspire-Kaspa-Wallet/blob/main/docs/PSKT_SELLER_OFFERS.md).
KaspaCom must still rerun its final provider-plus-adapter seller/buyer flow.
No live funds were moved for these regression tests.
